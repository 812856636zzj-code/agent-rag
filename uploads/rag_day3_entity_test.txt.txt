RAG API Day 3 实体抽取测试说明

当前系统提供 /upload、/search 和 /ask 三个核心接口。
/upload 接口负责接收文档文件，并将文件内容解析后保存为文档和 chunk。
/search 接口用于根据关键词检索 RAG_DOCUMENT_CHUNKS 表中的 chunkContent。
/ask 接口会先提取 keyword，然后调用 SearchService 检索相关内容。

文档上传后，系统会把文档基础信息写入 RAG_DOCUMENTS 表。
切分后的文本片段会写入 RAG_DOCUMENT_CHUNKS 表。
每个 chunk 会包含 documentId、chunkIndex、chunkContent 和 embeddingStatus 等字段。
当 embeddingStatus 为 PENDING 时，表示该 chunk 还未完成向量处理。
当 embeddingStatus 为 EMBEDDING_DONE 时，表示该 chunk 已完成后续处理。
如果处理失败，状态可能被标记为 FAILED 或 ERROR。
如果上传成功，可以返回 SUCCESS。

Day 3 新增 EntityExtractionService，用于在 saveChunks(...) 之后抽取实体。
EntityExtractionService 会调用 extractEntities(...) 方法，从 chunk 文本中识别 API、TABLE、FIELD、CONFIG、SERVICE、CLASS、METHOD、STATUS、LIBRARY 和 PATH 等实体。
抽取结果会写入 RAG_ENTITIES 表。
文档、chunk 和实体之间的关系会写入 RAG_DOCUMENT_ENTITY_LINKS 表。
RAG_ENTITIES 表中包含 ENTITY_NAME、ENTITY_TYPE 和 NORMALIZED_NAME 字段。

当前问答链路中，SearchService 负责检索。
ContextBuilderService 负责把 matchedChunks 整理成 structuredContext。
AnswerBuilderService 负责生成最终 answer。
AskContext、ChunkHit 和 SearchResult 是 /ask 流程中的主要数据对象。
ContextBuilderServiceImpl 中的 buildContext(...) 方法会处理 topChunks 和 answerHints。

当前项目使用 Spring Boot 构建。
解析 PDF 文档时可能使用 PDFBox。
数据库使用 Oracle。
代码中可能使用 Lombok 简化 getter 和 setter。
关键词检索可能使用 dbms_lob.instr。
配置文件包括 application.yml 和 application.properties。
常见配置项包括 spring.datasource.url 和 server.port。

上传文件默认路径可以是 D:/rag_api/uploads/。
代码路径示例包括 src/main/java/com/example/rag/service/。
