Add labeled correct, negated, and paraphrased variants before replacing this heuristic, and keep separate evidence for false positives and false negatives. This was left open because token presence cannot establish the asserted relation. Likely areas: `EvalServiceImpl.isAnswerTextHit`, `docs/eval/questions.json`, `EvalRunResult`, and `EvalQualityMetricsTest`.

4. **Keep unsupported raw retrieval text out of the model prompt.** Milestone 4 filters `AskResponse.sources` and the model's source preview, but `AnswerGenerateTool.buildLlmAnswerRequest` still copies the original `AgentToolInput.chunkHits` and `relationHits`, while `LangChain4jAnswerClient.buildPrompt` includes those raw hits and `structuredContext`. Thus a removed citation's text can still influence the generated answer. Define a supported-hit mapping from `SourceItem.chunkId`/`documentId`, rebuild prompt context and the rule-based fallback from that subset, and add a mixed-hit prompt test. Likely areas: `AnswerGenerateTool.buildLlmAnswerRequest`, `AgentAnswerAssembler`, `LangChain4jAnswerClient.buildPrompt`, and `AnswerGenerateToolTest`.

5. **Replace the first-sentence fallback for Chinese questions without identifiers.** Add Chinese term extraction or another measured relevance signal, and return no evidence when no sentence supports the question. `EvidenceSelectorImpl.extractQueryTokens` currently extracts Latin-style tokens; when there is no required table identifier and no scored sentence, `selectEvidenceSentences` falls back to the first sentence. Removing this without a Chinese relevance strategy could reduce valid recall, so it needs a labeled test set first. Likely areas: `EvidenceSelectorImpl`, `SentenceSplitterImpl`, `EvidenceSelectorImplTest`, and a new Chinese evidence fixture set.

6. **Publish the two latest eval files as one recoverable snapshot.** `EvalServiceImpl.runEval` writes `latest_eval_results.json` and then `latest_eval_report.md` before marking a run complete. A failure during the second write can leave a partial latest pair even while Oracle records the run as failed. Stage both files under the run ID, validate their contents, and only then publish a manifest or pointer after the database commit. Keep the history tables as the source of truth and test a forced filesystem failure. Likely areas: `EvalServiceImpl.writeEvalRunResults`, `writeEvalRunReport`, `EvalHistoryService.complete`, and `LocalEvalEndToEndTest`.

7. **Recover abandoned RUNNING evals after process termination.** `EvalHistoryService.begin` commits a RUNNING row before the answer loop. A process crash can leave that state forever. Define a bounded stale-run policy that marks only demonstrably abandoned rows as FAILED, including concurrent workers and clock skew, then test it with a controllable clock. Likely areas: `EvalHistoryService`, `EvalRunRecordRepository`, and a startup maintenance task.
