# Follow-up development TODOs

These are five concrete tasks left after the evidence and eval milestones. Each records the intended change, why it was not part of the current interval, and the likely code area. They are not claims that the feature already works.

1. **Make an empty Oracle database reproducible.** Add versioned DDL and a small seed dataset for `RAG_DOCUMENTS` and `RAG_DOCUMENT_CHUNKS`, then order the existing entity, relation, and memory migrations. The current `sql/` scripts cover later tables but omit the two base document tables; unverified DDL would have mixed migration work with evidence logic. Likely areas: `sql/`, `Document.java`, `DocumentChunk.java`, repository queries, and a migration test.

2. **Run a database-backed API regression in CI.** Start an Oracle-compatible test instance, apply schema and fixtures, then call `/ask` and `/eval/run` and compare generated files with explicit expectations. The current five test classes exercise logic without a live database; there is no running database in the local verification environment. Likely areas: `src/test/java/com/example/rag/controller/`, `src/test/resources/`, build/CI configuration, and `docs/eval/questions.json`.

3. **Improve wrong-answer and citation evaluation beyond token overlap.** Add a labeled set of paraphrases, negations, and misleading citations, then compare a semantic or claim-level checker against the deterministic heuristic before replacing it. The present `wrongAnswer`/`citationMatched` fields are review signals: a keyword match can still be false or unsupported. This needs labeled examples and explicit precision/recall targets. Likely areas: `EvalServiceImpl`, `EvalRunResult`, `docs/eval/questions.json`, and `EvalQualityMetricsTest`.

4. **Filter unsupported sources in mixed-evidence answers.** Keep supported sources but remove individual source entries with no valid evidence sentence before displaying citations or sending context to the answer provider. The new guard abstains only when all sources lack evidence; it does not yet clean a mixed list. This requires deciding how relation and SQL metadata sources are represented. Likely areas: `AnswerGenerateTool`, `AgentAnswerAssembler`, `SourceItem`, and `AnswerGenerateToolTest`.

5. **Replace the first-sentence fallback for Chinese questions without identifiers.** Add Chinese term extraction or another measured relevance signal, and return no evidence when no sentence supports the question. `EvidenceSelectorImpl.extractQueryTokens` currently extracts Latin-style tokens; when there is no required table identifier and no scored sentence, `selectEvidenceSentences` falls back to the first sentence. Removing this without a Chinese relevance strategy could reduce valid recall, so it needs a labeled test set first. Likely areas: `EvidenceSelectorImpl`, `SentenceSplitterImpl`, `EvidenceSelectorImplTest`, and a new Chinese evidence fixture set.
